1. Tổng quan hệ thống phân loại

Hệ thống tổ chức nội dung theo 4 layer từ rộng → hẹp. Mỗi layer là một Mongoose model, liên kết xuôi (cha → con) và liên kết ngược (con → cha) để truy vấn linh hoạt cả hai chiều.

Layer 1

MainTree — Ngành dọc

Cấp cao nhất: Adhesives, Coatings, Plastics, Rubber, Inks, Construction…

  • Slug unique (vd: adhesives)
  • Đa ngôn ngữ VI/EN
  • Icon + cover image
Layer 2

Category — Product Line

Dòng sản phẩm trong một ngành. Mỗi Category thuộc về đúng 1 MainTree.

  • vd: Hot Melt, Water-based, Solvent-based…
  • Slug (không bắt buộc unique)
  • Trỏ mainTree ngược lên Layer 1
Layer 3

MarketTree — Thị trường / Ứng dụng

Phân khúc thị trường hoặc use-case (Packaging, Automotive, Construction, Footwear…).

  • Có thể lồng nhau qua parent
  • Mỗi Market có applications[] và technologies[]
Layer 4

Product — Sản phẩm cụ thể

Đơn vị sản phẩm cuối cùng với mã, giá, TDS, attributes.

  • Trỏ về industries[] (MainTree)
  • Trỏ về productLine (Category)
  • Trỏ về marketIds[] (MarketTree)

4. Hai đường Market → Product

Từ MarketTree có hai cách đi tới Product: trực tiếp (marketIds[]) hoặc gián tiếp qua applications[]. Mỗi cách phục vụ một use-case khác nhau trên UI.

Đường trực tiếp

MarketTree.marketIds[] ↔ Product.marketIds[]

Quan hệ n-n đơn giản. Khi user vào trang Market, list "Tất cả sản phẩm của thị trường này" hiển thị.

  • Filter Product.marketIds = marketId
  • Index có sẵn trên marketIds
  • Phù hợp cho grid sản phẩm tổng quát
Đường gián tiếp

MarketTree.applications[].productIds[]

Mỗi Application là một use-case (vd: "Đóng gói thực phẩm"). CTA dẫn user sang trang Products filter sẵn theo Industry + Product Line.

  • Mỗi Application có linkedMainTree + linkedCategory
  • Filter Product.industries = linkedMainTree AND productLine = linkedCategory
  • Phù hợp cho "CTA → Xem sản phẩm phù hợp"

Ví dụ: Packaging market

marketIds[] Product.marketIds.includes('packagingId')
applications[] app.linkedMainTree=adhesives + app.linkedCategory=hotmelt

API gợi ý

GET /api/public/products?marketId=...&industry=...&category=...

Frontend dùng query string lọc theo slug/Id từ MainTree / Category / Market.

5. Application — sub-document trong MarketTree

MarketTree.applications là một mảng sub-document. Mỗi phần tử có id riêng và 3 liên kết: productIds[] (sản phẩm gắn trực tiếp), linkedMainTree (industry gợi ý), linkedCategory (product line gợi ý).

6. MarketTree.parent — cấu trúc cây

MarketTree.parent là self-reference (trỏ về chính MarketTree), cho phép dựng cây phân cấp thị trường không giới hạn cấp. 

Automotive (parent: null)
├── Automotive – Interior (parent: Automotive)
│   ├── Dashboard bonding (parent: Interior)
│   └── Seat foam (parent: Interior)
└── Automotive – Exterior (parent: Automotive)
    └── Wheel coating (parent: Exterior)

Packaging (parent: null)
├── Food Packaging (parent: Packaging)
└── Industrial Packaging (parent: Packaging)

Quy tắc

  • Root có parent = null
  • Child trỏ parent = id cha
  • Index { mainTree: 1, parent: 1, order: 1 } giúp sort theo cây
  • Có thể filter theo parent: null để lấy root

UI mapping

  • Markets.jsx → grid các root
  • MarketDetail.jsx → chi tiết + breadcrumb cha → con
  • MarketAppCard.jsx → card cho từng Application

7. Tóm tắt nhanh

Bốn layer, chín liên kết. Khi build API public:

Endpoint

GET /api/public/main-trees

Trả về danh sách MainTree active, sắp xếp theo order.

Endpoint

GET /api/public/categories?mainTreeId=...

Lọc Category theo MainTree, populate nhẹ nếu cần tên MainTree.

Endpoint

GET /api/public/markets?mainTreeId=...

Trả MarketTree + populate applications.productIds + linkedMainTree + linkedCategory.

Endpoint

GET /api/public/products?marketId|industry|category

Filter linh hoạt: marketIds, industries[], productLine. Đều có index.

Nhớ một dòng

MainTree 1-n Category 1-n Product và MarketTree n-n Product qua applications[].productIds[]
